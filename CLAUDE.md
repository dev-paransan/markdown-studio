# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-file, dependency-free Markdown editor — one self-contained HTML file with all HTML, CSS, and JavaScript inline. No build step, no package.json, no external libraries (the Markdown parser, syntax highlighter, and rendering logic are all hand-written).

## Active file (작업 기준 파일)

**이제부터 이 프로젝트의 작업 기준 파일은 `markdown-studio.html`이다.** 모든 신규 작업·수정·기능 추가는 이 파일에서 한다.

- **`markdown-studio.html` — 현재 활성 파일 / 정본.** "Markdown Studio" 에디션. 사이드바, 탭 기반 다중 문서, 최근 파일 목록(IndexedDB 핸들 저장), 실시간 미리보기, 언어 선택형 코드 하이라이트, Markdown / HTML / PDF 내보내기, 읽기전용 뷰어 모드를 갖춘 확장 버전.
- **`_archive/index.html` — 더 이상 활성 파일이 아님 (아카이브됨).** 초기 "Markdown Editor" 버전으로, 참고·이력 보관용으로만 남겨 둔다. 여기서 작업하지 말 것.
- **`index.html` (루트) — 앱이 아니라 리다이렉트 stub.** 루트(`/`) 접속 시 `markdown-studio.html`로 자동 이동시키는 몇 줄짜리 파일일 뿐이다. 여기에 기능을 넣지 말 것.

## Running

There's no build or install step. Either:

- Open `markdown-studio.html` directly in a browser, or
- Serve it locally (needed for some browser APIs — File System Access, IndexedDB — to behave consistently):
  ```
  python -m http.server 5173
  ```
  This matches the debug config in `.claude/launch.json`. Then visit `http://localhost:5173/markdown-studio.html`.

There are no tests, linter, or formatter configured in this repo.

## Architecture

`markdown-studio.html` is one self-contained file: inline CSS (`<style>`, ~lines 3–308), the DOM (sidebar / `<main>` / stage / status bar / overlays, ~310–402), and a single top-level `<script>` (~404–1483) holding all logic. Unlike the archived `index.html`, the script is **not** wrapped in an IIFE — its functions and `const`s live at script scope. Key pieces, roughly in data-flow order:

- **Multi-document model** — Open documents live in the in-memory `docs` array; each is `{ id, name, text, dirty, handle, readonly, guide? }`. `active` holds the current id, `cur()` returns the active doc, `seq` numbers new `무제-N.md` files. `select(id)` swaps the editor/preview to a doc, `drawTabs()` renders the tab bar (`#tabbar`), and `#empty` shows when nothing is open. **Nothing is open at startup** — there is no default document.
- **No localStorage** — Document content is *not* persisted to `localStorage` (a deliberate change from the archived editor). Unsaved buffers exist only in `docs`; a `beforeunload` handler warns when any doc is `dirty`. The only persistence is Recents (below).
- **Recents via IndexedDB** — `idb` wraps an IndexedDB database (name `"mds"`, **version 2**). Store `"recents"` (keyed by doc id): `touchRecent()` stores the `FileSystemFileHandle` when there is one (handles are structured-cloneable) or falls back to the raw `text`, keeping the 10 most recent and de-duplicating by `isSameEntry`. `loadRecents()` / `drawRecents()` render the sidebar list; clicking a recent reopens it **read-only**, re-requesting permission on the stored handle (`ensurePerm`) or using the fallback text. A second store `"settings"` (out-of-line key-value, via `idb.getVal/setVal/delVal`) holds app preferences — currently just the editable new-doc template (below). The `onupgradeneeded` guards each `createObjectStore` with a `.contains()` check so v1→v2 upgrades and fresh installs both work.
- **New-document template** — `newDoc()` fills the buffer from `newTemplate` (default = the built-in `SAMPLE`; `{{DATE}}` → today via `replaceAll`), which the user can edit and persist. `loadTemplate()` loads the saved value from `idb.getVal("newTemplate")` at startup; the `#tmplModal` overlay (a centered `<textarea>` + 저장/기본값으로/취소) edits it — `openTmpl`/`saveTmpl` (writes `idb.setVal("newTemplate", …)`)/`resetTmpl` (fills the box with `SAMPLE` but only persists on 저장)/`closeTmpl`. Reached via `data-a="template"`: the empty-state CTA, a `.d-only` sidebar button (desktop, when a doc is open), and a `.sheet-act` row in the mobile Recents bottom sheet.
- **Editor & preview** — A plain `<textarea id="editor">` (no highlighted-backdrop illusion — this file has **no editor-side syntax highlighting**) drives a line-number `#gutter` and the rendered `#preview`. `paint()` re-renders the preview from the active doc and updates the status bar (name + dirty dot, RO-toggle label, handle-link status, word/char count, caret via `caret()`). Rendering is **synchronous on every `input`** — there is no debounce or `scheduleRender`. Editor scroll drives the gutter (locked) and proportionally scrolls the preview, guarded by a `syncing` flag; Tab inserts two spaces.
- **Markdown renderer (`render(src, top)` + `inline(s)`)** — A hand-rolled, line-based block parser that recurses for blockquote contents (`render(…, false)`). It handles frontmatter (only when `top` && line 0), fenced code blocks, `hr`, raw-HTML blocks (gated by the `BLOCK_TAGS` set), ATX headings, blockquotes, lists (`listBlock` — ordered/unordered, `[x]`/`[ ]` task items, indent-continuation), tables (detected by the `|---|` separator row), and paragraphs. `inline()` shields inline code and raw inline HTML with placeholder sentinels (U+0000 / U+0001 markers) before escaping, then applies images / links / autolinks / bold / italic / `__bold__` / strikethrough. This is the **single source of truth for both the live preview and HTML/PDF export** — do not add a second parser.
- **Frontmatter card** — A leading `--- … ---` block is *rendered* as a metadata table (`.frontmatter`), not stripped. Array/list values (`[a, b]`, or multi-line `- item`) become `.fm-tag` chips. Both `SAMPLE` (the new-doc template, with `{{DATE}}` → today) and `GUIDE` begin with frontmatter.
- **Code highlighter (`HL`)** — A separate, self-contained regex highlighter (its own IIFE) used only inside fenced code blocks. `ALIAS` folds language names into one of `js | py | json | sql | bash | html | css`; `R` holds ordered `[class, regex]` rules per language; `compiled()` builds and caches one combined alternation `RegExp` per language and emits `<span class="c-*">` tokens (`c-com`, `c-str`, `c-key`, `c-fn`, …). It is deliberately approximate (the source comment says so) — not a real grammar; unknown languages render as escaped plain text. The token prefix is `c-*`, and `EXPORT_CSS` must define the same classes for exports to stay colored.
- **Per-block language selection** — Each fenced block gets a sequence index (`cbSeq`), with its raw code in `cbRaw[]` and source fence line in `cbLine[]` (`-1` for non-top-level blocks). `cbLang` maps block index → user-chosen language; `effLang()` resolves *user pick → fence tag → `DEFAULT_LANG` (`python`)*. Each block renders a `.cb-lang` `<select>` plus a `.cp` copy button. Changing the dropdown on a **top-level, editable** block rewrites that block's ```-fence in the source text (marking the doc dirty, so the choice round-trips to save); on read-only or nested blocks it only re-highlights the DOM.
- **File I/O** — File System Access API first (`FSA` flag): `showOpenFilePicker` (`mode: "read"` for Viewer opens vs `"readwrite"`), `showSaveFilePicker`, and `createWritable` in `writeTo()`; `isSameEntry` de-dupes already-open files and `ensurePerm` (query/request inside a user gesture) guards access. Fallbacks when the API is absent: a hidden `<input id="picker">` for open, and a Blob download (`legacySave` / `downloadBlob`) for save. Drag-and-drop (`handleDrop`) collects `DataTransferItem`s *synchronously* (they invalidate after `await`), prefers `getAsFileSystemHandle`, and filters names by `MD_RE`. **Capacitor native caveat:** the Android WebView *exposes* `showOpenFilePicker`/`showSaveFilePicker` but the pickers don't actually work (save/open silently no-op), so `FSA` is force-disabled when `window.Capacitor.isNativePlatform()` (the `NATIVE` const) — this routes save/open/export through the `<input>`/`<a download>` fallbacks, which `android-app/www/capacitor-bridge.js` intercepts to do the real native Filesystem write + Share. That bridge is a separate `<script>` injected at EOF by `android-app/scripts/sync-web.mjs`; its idempotency guard checks for the **full `<script>` tag**, not the substring `"capacitor-bridge.js"` (a bare mention of that string in a source comment must not suppress injection). **Open-with / share (.md files):** `AndroidManifest.xml` gives `MainActivity` VIEW intent-filters (`text/markdown`, `text/x-markdown`, `text/plain`, plus `application/octet-stream`+`.md`/`.markdown`/`.mdown` pathPatterns) and a SEND filter, so the app appears in the system chooser for markdown/text files. `MainActivity.java` (native) reads the incoming `content://`/`file://` URI (or `EXTRA_TEXT`) via `ContentResolver`, then calls the canonical's `window.__mdsOpenIncoming({name,text})` — a small generic hook next to `newDoc()` that opens the text as a new editable doc — retrying `evaluateJavascript` until that function exists (cold-start race). A `mds_consumed` extra guards against Android delivering the same launch intent to `handleFileIntent` twice (it fires in both `onCreate` and a follow-up), which would otherwise open two identical tabs.
- **Read-only / Viewer mode** — Any doc can be `readonly`; `body.ro` hides the editor and splitter and gives the preview full width. `toggleRO()` (⌘E or the status-bar button) flips it (confirming if dirty). The "열기 (Viewer)" action and the syntax `GUIDE` open read-only.
- **Export (`buildStandaloneHtml`)** — Clones the live `#preview`, strips `.cb-bar` toolbars, and inlines `<img>`s to base64 data URIs (`inlineImages`; unreachable images stay as external links and are counted). The clone is wrapped with a **separate static `EXPORT_CSS`** string — its own light "paper" stylesheet plus the `c-*` highlight colors and `@media print` page rules, distinct from the app's live `<style>`. `exportHtml()` saves it (FSA picker or download); `exportPdf()` writes it into a hidden `<iframe>` and calls `print()` — no PDF library, relying on the browser's "Save as PDF". The "다른 이름으로" action opens the positioned `#saveMenu` (md / html / pdf).
- **Theming** — Fixed light "paper" theme only. Colors are CSS custom properties on `:root`; there is **no dark theme, no `data-theme`, no `prefers-color-scheme`** (a deliberate simplification from the archived editor).
- **Layout & chrome** — Collapsible sidebar (`body.collapsed`, ⌘B / toggle button / logo mark). A draggable `#split` resizes the editor pane's flex-basis (15–85 %, double-click → 50 %, arrow keys). Keyboard: ⌘S / ⇧⌘S save / save-as, ⌘N new, ⌘O / ⇧⌘O open / open-viewer, ⌘E toggle RO, ⌘W close, ⌘B sidebar, ⌘/ guide. Transient messages go through `toast()`.
- **Mobile chrome (`@media (max-width:820px)`)** — Below 820px the desktop sidebar/split are replaced by a **mobile-only, top-toolbar UI** (all rules media-scoped; desktop untouched, and the mobile DOM — `#mbar`, `.act.m-only`, `#mSheet` — is `display:none` on desktop). A top app bar `#mbar` holds the logo, the active doc name (via `paintMobile()` in `paint()`), and an **Edit / View segmented toggle** that swaps `body.m-edit`/`body.m-prev`; instead of the split, only one full-width pane shows at a time (`body.m-edit:not(.ro) #pvPane`, `body.m-prev:not(.ro) #edPane`). Tapping Edit on a read-only doc calls `toggleRO()` to make it editable. (Per user request the **entire mobile UI is in English** while the shared desktop layout stays Korean. Two mechanisms keep them separate on the same DOM: **(a) `.d-only`/`.m-only` paired spans** for static text — generic rules hide `.m-only` on desktop and `.d-only` on mobile (a superset of the older `.act`-scoped rules), so e.g. the `#empty` heading/description/CTAs and the `#stFind` label carry both a Korean `.d-only` span and an English `.m-only` span; **(b) a `T(ko, en)` JS helper** — `T` returns `en` when `isMobileUI()` (`matchMedia("(max-width:820px)")`) for strings built in JS: `#stRo` (`Read-only · Edit` / `Editing · Make read-only`) and `#stWrap` (`Wrap: On`/`Wrap: Off`); the `#stFont` preset `<option>`s are relabeled to English at init on mobile. `#stCount` was already English. The **Edit / View toggle** is a mobile-only element so its text is set directly. Document *content* — the `SAMPLE` new-doc template and the `GUIDE` — stays Korean; only chrome is translated.) The sidebar reflows into a horizontal, scrollable **text toolbar**: on mobile the SVG icons are hidden and each button shows its English `data-mtitle` via `::after { content: attr(data-mtitle) }` (New·Open·Recents·Save·Save As), styled as white chips with a `--sb-line` border. Buttons that don't work on mobile (`data-a="openfolder"`/`print`/`guide`, marked `.d-only`) plus the guide separator are hidden, and the editable-open `data-a="open"` is **also `.d-only`** (mobile hides it), so the eye button `data-a="openro"` — labeled `Open` via `data-mtitle` — is the sole open button; a mobile-only `data-a="recents"` button opens a **bottom sheet** `#mSheet` listing Recents (`drawRecents()` mirrors the list into `#recentsM`; clicks reuse `openRecentById()`). The document `#tabbar` is shortened to `min-height:40px` on mobile (desktop 57px). The status bar becomes a single scrollable row with redundant items hidden. A **long-press tooltip** (`#mTip`) still shows each button's `data-mtitle` (falling back to `title`) on touch-and-hold (~450ms) — now somewhat redundant with the visible text label but harmless — suppressing the follow-up click so the hold doesn't also fire the action; desktop mouse users keep the native Korean `title` hover tooltip. All action buttons still work through the existing global `[data-a]` delegation on `document.body`, so the mobile toolbar needs no separate wiring. This shared-canonical mobile UI is what the Android app (`android-app/`) ships.

The UI strings and comments in the source are in Korean; keep new UI-facing strings consistent with that unless told otherwise.

The archived original single-pane editor lives at `_archive/index.html`. It shares the "hand-rolled parser is the single source of truth" and "self-contained HTML export" ideas but is otherwise an independent, smaller codebase (highlighted-backdrop editor with `tok-*`/`hl-*` highlighters, light/dark theme via `data-theme`, `localStorage` persistence). It is no longer maintained — do not use it as a reference for `markdown-studio.html`.
