# AI 산출물 마크다운 전사 공통 규칙

## 요약

- AI가 생성하는 **모든** 마크다운(.md) 산출물은 사내 공용 저장소에 등록되며, 단일 진입점(MCP)을 통해 전사에 제공된다.
- 따라서 파일 상단의 **프론트매터(YAML)가 곧 검색·접근통제 메타데이터**이며, 각 필드 값은 통제 어휘(고정 목록)로 못 박는다.
- 파일명은 `주제_작성팀_YYYYMMDD_vN.md`(YYYYMMDD = **개정일**), 최초작성일은 프론트매터에 둔다.
- 작성팀은 **사용자 프로필의 소속부서명**에서 취득하며, 없으면 **생성 전 질문**한다.
- MCP 제공 대상은 **공개·대외비**이며(대외비는 본문 전체 제공), **기밀은 이 저장소에 등록하지 않는다.**

---

## 1. 목적·적용범위

□ 목적 — AI가 생성하는 마크다운 산출물의 형식·메타데이터·저장·제공 기준을 통일하여, 사내 공용 저장소 등록과 MCP 기반 검색·활용의 품질과 안전성을 확보한다.

□ 적용범위
- 대상: 사내 기업용 AI가 생성하는 **모든 마크다운(.md) 문서**.
- 제외: 개인 작업용 임시 메모, 코드 저장소 내 기술 주석, 외부 고객 대상 산출물(범위 밖).
- 기밀 등급 문서는 본 규칙의 파일명·본문 형식은 따르되, **MCP 대상 저장소에는 등록하지 않는다**(6장).

---

## 2. 작성 전 확인(Step 0) — 소속부서 게이트

□ 파일 생성 **전에** 작성자의 소속부서명을 확보한다.
- 사용자 프로필·설정에서 소속부서명을 취득한다.
- **프로필에 소속부서명이 없으면 파일을 생성하지 않고 사용자에게 먼저 질문한다.** 추측으로 채우지 않는다.
- 취득한 소속부서명은 파일명의 `작성팀` 토큰과 프론트매터 `소속팀`·`작성부서`에 사용한다.

---

## 3. 파일명 규칙

□ 형식

```
주제_작성팀_YYYYMMDD_vN.md
```

□ 필드 정의

| 토큰 | 내용 | 규칙 |
|---|---|---|
| 주제 | 문서 핵심 주제(한글) | 공백은 하이픈(-)으로 치환. 밑줄(_) 사용 금지(필드 구분자와 충돌) |
| 작성팀 | 작성(요청) 부서명 | 프로필 소속부서명(Step 0). 공백은 하이픈. 개인명은 프론트매터에 기재 |
| YYYYMMDD | **개정일(현행 버전일)** 8자리 | 개정 시마다 갱신. 최초작성일은 프론트매터로 관리 |
| vN | 버전(정수) | 개정 시 증가(v1, v2 …). 프론트매터 `버전`과 일치 |

□ 문자 규칙
- 허용: 한글, 영문, 숫자, 하이픈(-).
- 금지: 공백, 밑줄(주제 내), `/ \ : * ? " < > |`.
- 예) `데이터카탈로그-운영기준_AI데이터플랫폼팀_20260811_v1.md`

---

## 4. 저장 위치·폴더 구조

□ 기준 — **작성(요청) 부서** 기준의 본부·팀별 트리로 등록한다. 유형·주제는 폴더로 나누지 않고 메타데이터·태그로 식별한다.

```
/{본부}/{팀}/{파일}.md
예) /AX본부/AI데이터플랫폼팀/데이터카탈로그-운영기준_AI데이터플랫폼팀_20260811_v1.md
```

□ 원칙
- 한 문서는 하나의 정식 경로에만 둔다(중복 배치 금지). 타 부서 관련성은 태그로 표현한다.
- 기밀 문서는 이 트리에 두지 않고 접근통제된 별도 영역에 보관한다(MCP 미대상).

---

## 5. 프론트매터(메타데이터) 표준

□ 모든 문서는 아래 필드를 **프론트매터에 필수**로 포함한다. 값은 통제 어휘(부록 C)를 따른다.

```yaml
---
제목: "문서 제목"
유형: 보고서                # 보고서|규정지침|기술문서|회의기록|리서치|데이터카탈로그|기타
작성자: 홍길동              # 개인명
소속팀: AI데이터플랫폼팀
작성부서: AI데이터플랫폼팀    # 폴더 분류 기준(작성·요청 부서)
최초작성일: 2026-08-11      # 고정
개정일: 2026-08-11         # 현행 버전일 = 파일명 날짜
버전: v1
상태: 초안                 # 초안|검토|확정|보류|폐기
보안등급: 대외비            # 공개|대외비|기밀
사내공개범위: 본부          # 전사|본부|팀|지정 (라벨)
MCP공개: true             # 파생값 — 6장 규칙으로 자동 산출
태그:
  - 유형/보고서
  - 영역/데이터거버넌스
  - Snowflake
주요내용: "한 줄~세 줄 요약(검색·MCP 응답에 그대로 노출)"
---
```

□ 필드 구분

| 구분 | 필드 |
|---|---|
| 사용자 지정 필수 | 제목, 작성자·소속팀, 최초작성일·버전, 상태·태그, 보안등급, 사내공개범위, 주요내용 |
| 운영 필수(자동/파생 포함) | 유형, 작성부서, 개정일, MCP공개 |

□ 규칙
- `주요내용`은 검색 결과·MCP 응답에 그대로 노출되므로, 문서를 열지 않고도 판단 가능한 3줄 이내 요약으로 작성한다.
- `MCP공개`는 수작업 오류를 막기 위해 등록 파이프라인에서 자동 산출한다(6장).

---

## 6. 태그 체계

□ 계층형(통제) + 자유(비통제) 혼용.

□ 계층형 통제 태그 — `분류축/값` 형식. 부록 C의 허용 목록에서만 사용.
- `유형/…`, `영역/…`, `팀/{부서명}`, `규제/…`

□ 자유 태그 — 통제 목록 밖의 키워드. 소문자·명사 위주, 1~2어절. 예) `Snowflake`, `카탈로그`, `RAG`

□ 원칙 — 계층형 태그로 대분류를 고정하고, 세부 주제는 자유 태그로 보완한다. 신규 통제 태그는 데이터 거버넌스 담당 검토 후 부록 C에 반영한다.

---

## 7. 보안등급·공개범위·MCP 제공 규칙

□ 두 축을 분리 운영한다.
- **보안등급** = 문서 기밀성 (공개 / 대외비 / 기밀)
- **사내공개범위** = 열람 대상 라벨 (전사 / 본부 / 팀 / 지정)

□ MCP 제공 범위 — **공개·대외비**를 제공하며, **대외비는 본문 전체를 제공**한다.

| 보안등급 | MCP 등록 | 처리 |
|---|---|---|
| 공개 | ○ | 공용 저장소 등록·MCP 제공 |
| 대외비 | ○ | 등록·제공, **본문 전체 제공** |
| 기밀 | ✕ | 공용 저장소 미등록. 접근통제 별도 영역 보관 |

□ `MCP공개` 파생 규칙
```
MCP공개 = (보안등급 ∈ {공개, 대외비}) AND (상태 ≠ 폐기)
```
- 기밀은 애초에 등록되지 않으므로 `MCP공개=false` 이자 별도 영역 대상.
- 폐기 문서는 파일은 보존하되 MCP 제공에서 제외한다.

□ 접근통제 — **IdP 신원 기반 필터는 적용하지 않는다.** `사내공개범위`는 운영 라벨로만 유지한다.
- 결과적으로 MCP 접근이 가능한 사용자에게 공개·대외비 문서의 본문 전체가 제공된다.
- 따라서 **대외비 판정은 신중히** 하고, 노출 시 문제가 되는 내용은 기밀로 분류하여 등록에서 제외한다.

---

## 8. 버전·개정 관리

□ 개정 시 **구버전을 보존**하고 **새 파일(버전 접미사 증가)**을 생성한다.
- 파일명 날짜는 **개정일로 갱신**, `_vN` 증가.
- 프론트매터 `개정일`·`버전` 갱신, `최초작성일`은 유지.
- 본문 개정 이력에 변경 요약 1행 추가.

□ 개정 이력(본문 필수 블록)

| 버전 | 개정일 | 작성자 | 변경 요약 |
|---|---|---|---|
| v1 | 2026-08-11 | 〈작성자명〉 | 최초 작성(확정) |

---

## 9. 상태 생애주기

```
초안 → 검토 → 확정 →(개정 시 새 버전)
              │
              └→ 보류 / 폐기
```

- 초안: 작성 중 · 검토: 리뷰 중 · 확정: 승인 완료 · 보류: 진행 중단 · 폐기: 효력 상실(MCP 제외, 파일 보존).
- 초안→확정은 동일 버전 내 상태 전환이며, 확정 후 내용 변경 시 버전을 올린다.

## 10. 준수 체크리스트

- [ ] Step 0 — 소속부서 확보(없으면 생성 전 질문)
- [ ] 파일명 `주제_작성팀_YYYYMMDD_vN.md`, 금지 문자 없음, 날짜=개정일
- [ ] 프론트매터 필수 필드 완비, 값이 통제 어휘 준수
- [ ] `주요내용` 요약 3줄 이내
- [ ] 저장 경로 `/본부/팀/`(작성 부서 기준)
- [ ] 보안등급 기밀 → 공용 저장소 미등록(별도 영역)
- [ ] 공통 골격(요약·본문·개정 이력·참고근거) + 유형별 블록 구비
- [ ] 개정본이면 구버전 보존, 버전·개정일 갱신(최초작성일 유지)

| 유형 | 추가블록 |

## 부록 D. 운영 유의사항

- 소속부서명이 프로필에 없으면 파일을 생성하지 않고 먼저 질문한다.
- 대외비는 본문 전체가 MCP 사용자 전원에게 노출됨을 전제로 등급을 판정한다. 노출이 부적절하면 기밀로 분류한다.
- 기밀은 공용 저장소·MCP 대상이 아니며 접근통제 별도 영역에 보관한다.
- 본 규칙을 강제하는 스킬: `ai-markdown-standard` (파일명·프론트매터·본문 골격 생성 및 검증).

- 以上 -
